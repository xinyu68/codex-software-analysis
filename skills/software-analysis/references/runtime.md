# 运行观察与接口验证

依据用户当前目标选择动态观察，避免把功能分析自动扩大为持续取数服务。

运行验证记录目标版本、运行环境、操作、输入输出、时间和观察途径。读取既有日志、HAR 与运行材料和发起新请求是不同操作；`analysis_import_evidence` 和 `har` 模式只读取已有文件。

对于数据接口，分别记录：

- 协议与入口：HTTP、WebSocket、IPC 或本地数据库
- 来源：静态代码、已有记录、当前实际运行
- 会话：本次运行所需的授权机制，不公开凭据值
- 请求及响应：输入参数、返回结构和错误状态
- 更新机制：服务器推送、心跳、轮询；刷新画面不等于每次发送 HTTP 请求
- 验证边界：恢复结构、握手成功、取得业务数据、与页面一致，分别说明

客户端库的默认头、压缩、心跳和连接生命周期会影响实际行为。需要兼容原协议时按证据实现，不凭空编造客户端信息，不承诺服务端无法区分客户端。

出现验证页、权限拒绝或会话限制时保留诊断。此插件不内置代理/证书替换、登录破解、验证码绕过或封禁规避流程，也不自动回放记录中的 URL。需要进一步验证而缺少授权/运行条件时说明具体缺口，继续可完成的本地分析。

插件的 `analysis_close_project` 只能回收该工作台拥有的分析命令进程。REA 原生会话、设备 App、浏览器会话、模拟器和其他工具启动的采集进程，应由相应所有者关闭并核验。关闭时保留分析材料，不删除日志掩盖未完成或失败步骤。
